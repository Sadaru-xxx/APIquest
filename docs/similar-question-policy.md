# 類題ポリシー

2026-11-11 に決定。類題は「演習中に間違えた直後」と「復習」で別のものを出します。各表問題に「即時類題」と「復習バリエーション」を1問ずつ付け、3問を1組として管理します。どちらも JDK 17 での検証を必須とし、検証を通らない問題は収録しません。

## 3問の役割

| 種類 | ID | 出すとき | 目的 | 作り方 |
| --- | --- | --- | --- | --- |
| 表 | oc-18a | 演習・模擬試験 | 得点力の判定 | ― |
| 即時類題 | oc-18b | 演習中に表を間違えた直後 | 解説を理解できたかの確認 | 表と同じコード構造・同じ選択肢構成。変えるのは数値リテラル、変数名・クラス名、文字列の中身だけ。演算子・制御構造・型は変えない |
| 復習バリエーション | oc-18c | 復習(1日後・3日後・7日後) | 汎化と忘却の防止 | 同じトピック・同じ難易度で、別の角度から問う(例: 表が && と \|\| の短絡評価なら、こちらは短絡しない & と \| )。表との違いを `variationNote` に1行で書く |

## 演習中の即時類題

不正解 → 解説 → 「類題に挑戦」で、同じ組の即時類題(b)を出します。その即時類題をすでに解いていれば、同じトピックでまだ出していない即時類題を出します(`app/src/views/Practice.tsx` の `similarFor`)。

## 復習で出す問題

復習では、間違えた問題そのものは出しません。復習の対象は「問題」ではなく「組(組 ID)」で、回ごとに次の問題を出します(`app/src/store.ts` の `reviewQuestionFor`)。

1. 1日後: その組の復習バリエーション(c)
2. 3日後: 同じトピックの別の組の復習バリエーション。なければ別の組の表
3. 7日後: 2と同じ選び方で、まだその復習で出していない問題

2と3で候補がすべて出題済みなら、その組の復習バリエーションに戻ります。間違えたらその組を 1日後に戻します。即時類題を間違えた場合も、同じ組を 1日後に登録します。模擬試験では各組から表か復習バリエーションのどちらか1問を出し、表とほぼ同じ即時類題は使いません。

## 品質チェック

既存の JDK 17 検証に次の2つを加えて自動化しています(`tools/verify-questions.mjs`、`authoring/build-questions.mjs`)。

- 即時類題の構造チェック: 表と即時類題のコードを字句に分け、識別子とリテラルを伏せ字にした列が一致すること。選択肢の数と選択数も一致すること
- バリエーションの差分チェック: 同じ処理で列が表と一致しないこと(数値を変えただけのものを弾く)。論点が本当に別の角度かは、問題ごとに「表との違い」(`variationNote`)を 1行で記録してレビューで確認する

表と即時類題の正解の記号が同じ場合は警告を出します(エラーにはしない)。

## 分野3の移行記録

ポリシー決定前の分野3は、表(a)と類題(b)の2問1組でした。次のように移行しました。

- 当時の類題のうち、数値と変数名だけが違うのは oc-09・oc-12 の2組でした。この2組は類題を即時類題のままにして、復習バリエーションを新しく作りました。
- 残り23組は類題が演算子や型まで変えていたので、類題を復習バリエーション(c)に移し、即時類題(b)を新しく作りました。
- 新規作成は合わせて25問です。移行は 2026-11-11 に完了し、75問すべて JDK 17 で一致、構造チェック 25組で問題 0件です。oc-09 の即時類題は、表と比較演算子(>=)をそろえて構造チェックを通る形に直しました。

アプリの学習履歴(version 1)に残っている当時の類題の ID は、`app/src/store.ts` の移行処理で新しい ID に読み替えます(oc-09・oc-12 以外の `oc-NNb` → `oc-NNc`)。
